# Lecture 14 live demo — the "MS analysis assistant" (a ReAct agent)

A self-contained, **framework-free** agent for the Lecture 14 live demo. No
LangChain, no LlamaIndex — the whole agent is one readable file, `qc_agent.py`:
plain-function **tools**, a raw **LLM call**, and a ~30-line **reason → act loop**.

It reproduces the five demo beats on the slides, on the **same QC table and
numbers as your handout** (`lecture14_followalong.tex`, run **QC-04**):

```
READ the QC table → ANALYZE against spec limits → PLOT the 3 metrics
→ FLAG the out-of-range run (QC-04) → DRAFT a QC summary for a human
```

## Run it

```bash
cd demos/lecture14_agent

# Offline (default): no API key, no network — never fails live.
python3 qc_agent.py

# Real LLM via a raw HTTP call to any OpenAI-compatible endpoint (no SDK):
export OPENAI_API_KEY=sk-...
export OPENAI_MODEL=gpt-4o-mini          # optional
python3 qc_agent.py --llm openai

# A LOCAL model works too (e.g. Ollama) — same code, just point the base URL:
export OPENAI_BASE_URL=http://localhost:11434/v1
export OPENAI_MODEL=llama3.1
export OPENAI_API_KEY=ollama
python3 qc_agent.py --llm openai
```

Only dependency for the plot is `matplotlib` (and if it's missing, the demo
still runs and just skips the PNG). Output plot: `qc_plot.png`.

## What to say while it runs (the teaching points)

- **An agent = LLM + tools + a loop.** Point at the three sections of the file.
- **The model only ever writes TEXT.** When it wants to act, it writes a line
  like `Action: check_limits`. *Our* code parses that line, runs the matching
  Python function, and feeds the result back as `Observation:`. The model never
  touches your files — that's what makes **restricted tools** a real guardrail.
- **The final answer is built from observations, never invented** — tie this to
  Quiz 14 Q1(b) (spotting a fabricated claim) and Q4 (hallucination).
- **It hands off to a human** ("please verify before releasing results") — tie
  to Q3 (what must stay human-reviewed).
- Colour-coding in the terminal matches the deck: teal **THOUGHT** (reason),
  amber **ACTION** (act), grey **OBSERVATION**, red **ANSWER**.

## Fallback (the deck promises the demo never fails live)

The default `--llm offline` backend is a tiny **scripted planner** — not a real
model, it just returns the correct reason→act steps so the demo always runs.
The loop, the parsing, the tools, and the grounded final answer are all real;
only the "thinking" is canned. Run it once before class and the printed
transcript *is* your pre-recorded fallback.

## The spec limits (from the QC SOP, hard-coded for a self-contained demo)

- mass error within **±2 ppm**
- resolution **> 30,000**
- TIC within **8–12** (×10⁶)

QC-04 = `+5.6 ppm · 22,300 · 3.1` → breaks all three.
