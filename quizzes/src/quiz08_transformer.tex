% =========================== Q1 ===========================
\textbf{1. Context is a blend of values.}\; {\small In attention, a token's output is a weighted average
of the other tokens' vectors --- and that output \emph{is} the ``context'' it gathers. The three roles: the
\textbf{query} asks, the \textbf{keys} set the weights, the \textbf{values} carry the content.}

\vspace{4pt}
\textbf{(a)} Which of \textbf{query}, \textbf{key}, or \textbf{value} carries the actual content that ends up
in a token's output --- its context?\hfill $\rightarrow$\;\rb{value}{3.0cm}

\vspace{3pt}
\textbf{(b)} A peak attends over four peaks with weights $0.1,\ 0.7,\ 0.15,\ 0.05$. Its new context vector is
built mostly from which peak's value?\hfill $\rightarrow$\;\rb{peak 2 (weight 0.7)}{3.8cm}

\work{0.4cm}

\keybox{(a) The \textbf{value}. The query and keys only decide \emph{how much} of each token to take; the
\textbf{values} are the content that is actually blended into the output, so the ``context'' a token ends up
with is a weighted sum of \emph{values}. (b) \textbf{Peak 2} --- its weight $0.7$ is larger than all the
others combined, so it dominates the blend. Weights are just the mixing proportions.}

\vspace{2pt}\hrule\vspace{5pt}

% =========================== Q2 ===========================
\textbf{2. Cross-attention: the encoder's K,V \emph{is} the context.}\; {\small In an encoder--decoder
(e.g.\ Casanovo: spectrum in, peptide out) the \textbf{encoder} reads the whole spectrum once and turns it
into a set of \textbf{keys and values} --- its memory of the spectrum. The \textbf{decoder} then writes the
peptide one residue at a time, each step sending a query into that encoder K,V (\emph{cross-attention}).}

\vspace{4pt}
\textbf{(a)} As the decoder writes residue 1, then 2, then 3, \dots, is the encoder's K,V \emph{recomputed
every step} or \emph{computed once and held fixed}? What does it represent?

\work{0.95cm}
\ifsolution\else\blk{\linewidth}\fi

\vspace{3pt}
\textbf{(b)} Suppose that halfway through writing the peptide you \textbf{swap in the K,V from a different
patient's spectrum}. What happens to the rest of the peptide, and why?

\work{0.95cm}
\ifsolution\else\blk{\linewidth}\fi

\keybox{(a) \textbf{Computed once and held fixed} for the whole decode --- it is the model's \textbf{context /
memory of the spectrum}. Every residue the decoder writes queries the \emph{same} encoder K,V, which is how
each output token can look back at the whole spectrum. (b) The remaining residues would be sequenced against
the \textbf{wrong spectrum}, giving a \textbf{wrong / incoherent peptide} --- because the encoder's K,V \emph{is}
the context the output is grounded in. Change the context and you change what the decoder is ``reading.''}

\vspace{2pt}\hrule\vspace{5pt}

% =========================== Q3 ===========================
\textbf{3. Match each data type to a tokenization strategy.}\; {\small A transformer eats a sequence of
vectors, so MS data must be turned into tokens. Match each data type to the one strategy that fits it
best (each used once), using the decision chart from the slides.}

\vspace{4pt}
\textbf{(a)} An \textbf{imaging-MS image} (a 2D picture, one spectrum per pixel)\hfill
$\rightarrow$\;\rb{patches + linear projection (ViT)}{5.2cm}

\vspace{3pt}
\textbf{(b)} A \textbf{raw binned spectrum} (a dense 1D vector of $\sim$6{,}000 intensities)\hfill
$\rightarrow$\;\rb{CNN front-end}{5.2cm}

\vspace{3pt}
\textbf{(c)} A \textbf{peak list} (a sparse set of $m/z$ + intensity peaks)\hfill
$\rightarrow$\;\rb{peak-as-token (Casanovo)}{5.2cm}

\vspace{4pt}
\begin{center}
{\small \textbf{Word bank:}\;\; chunk into patches + linear projection (ViT) \;$\cdot$\;
CNN front-end \;$\cdot$\; peak-as-token (Casanovo)}
\end{center}

\keybox{(a) \textbf{Patches + linear projection (ViT-style)} --- a 2D image is cut into equal patches, each
projected to a token vector. (b) \textbf{CNN front-end} --- a dense, evenly-sampled 1D signal is best
condensed by a small 1D CNN that emits token embeddings (local peak-shape detection first, then the
transformer mixes globally). (c) \textbf{Peak-as-token} --- a sparse peak list is already a natural set of
tokens; each peak becomes one token carrying its $m/z$ and intensity, exactly how Casanovo reads a spectrum.}

\vspace{2pt}\hrule\vspace{5pt}

% =========================== Q4 ===========================
\textbf{4. Fine-tune, or train from scratch?}\; {\small You need a classifier for a new MS assay. You have
\textbf{800 labeled spectra}, and access to a transformer someone \textbf{pretrained on 2 million spectra}.}

\vspace{3pt}
\textbf{(a)} Would you \emph{train a new model from scratch} on your 800 spectra, or \emph{fine-tune} the
pretrained one?\hfill $\rightarrow$\;\rb{Fine-tune}{3.2cm}

\vspace{3pt}
\textbf{(b)} In one sentence, why?

\work{1.0cm}
\ifsolution\else\blk{\linewidth}\fi

\keybox{(a) \textbf{Fine-tune} --- freeze the pretrained body, bolt on a small new classification head, and
train mostly that head on the 800 labels (optionally unfreeze a little of the top with a much smaller
learning rate). (b) \textbf{800 labels are far too few to train a transformer's millions of weights from
scratch} --- it would overfit or collapse toward the majority class --- whereas \textbf{the pretrained body
already learned general spectral features from the 2 million spectra}, so you only need to fit a small head,
which 800 labels can do well. (Either reason earns full credit.)}
